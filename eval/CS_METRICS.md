# CS 평가 지표 (사전 등록)

새 CS 구조(큰 카테고리 분류 → 필터 검색)를 평가하기 전에 판단 기준을 고정한다.
결과를 본 뒤 이 문서의 기준을 바꾸지 않는다. 바꿔야 하면 이유와 날짜를 아래 "변경 이력"에 남긴다.

## 지표 정의

| 단계 | 지표 | 비교 대상 | 계산 |
|---|---|---|---|
| 검색 | Hit@1, Hit@3 | 가져온 문서의 CS 구분 vs 정답 구분(대안 포함) | 같은 구분이 여러 번 나오면 하나로 센다 |
| 검색 | MRR | 정답 구분의 첫 순위 | 1/순위, 3위 안에 없으면 0 |
| 검색 | 큰 카테고리 분류 정확도 | 분류기가 고른 클레임 카테고리 vs 정답 구분의 카테고리 | 새 구조에서만 |
| 생성 | 충실도 | 답변 주장 vs 챗봇이 실제로 받은 문서 | 주장이 1개 이상이고 모두 뒷받침되면 성공 |
| 최종 | **최종 답변 정확도** | 답변 주장 vs 정답 문서(원문 + 검수한 고객 문구) | 주장이 1개 이상이고 모두 뒷받침되면 성공 |
| 최종 | 포괄성 | 답변 vs 정답 고객 문구 중 문의 상황에 해당하는 핵심 내용 | 덮은 핵심 내용 비율 |
| 최종 | 내부 정보 노출 | 답변에 내부 정책 용어가 나오는가 | `LEAK_TERMS` 키워드 검사 |
| 시스템 | 지연, 비용 | 서버 SSE 측정, LLM 사용량 | p50, 평균 |

## 판단 기준

- 주 지표: 최종 답변 정확도. 새 구조 채택 조건은 현재 서비스 대비 차이의 95% CI(CS 구분 단위 부트스트랩) 하한이 0보다 큰 것이다.
- 안전 기준(하나라도 어기면 채택하지 않는다):
  - 내부 정보 노출 0건
  - 포괄성 하락 5%p 이내
  - CS 응답 완료 p50 증가 1초 이내
- 검색 지표와 충실도는 원인 설명용이다. 채택 판단에 쓰지 않는다.
- 검정은 주 지표 비교 하나만 한다(McNemar 정확 검정 + 구분 단위 부트스트랩).

## 데이터

- 조정: dev(25) + dev2(75). 분류기 프롬프트와 생성 규칙은 여기서만 고친다.
- 최종 평가: 새 test2(100, 다른 모델이 블라인드 작성). 시스템마다 한 번만 실행한다.
- 기존 test(100)는 실패 사례를 이미 읽었으므로 최종 판단에 쓰지 않는다.

## 채점자 검증

LLM 채점 지표는 사람 판정과 비교해 일치도를 보고한다. 판정 시트의 답변은 판정자가 처음 보는 것만 쓴다.

| 지표 | 사람 판정 |
|---|---|
| 최종 답변 정확도, 충실도 | 주장 40개 (채점자 판정 기준 근거 있음·없음 반반) |
| 포괄성 | 답변 15개의 핵심 내용별 포함 여부 |
| 내부 정보 노출 | 답변 30개를 읽고 다른 표현으로 샌 경우가 있는지 |

## 알려진 한계

- 질문은 실제 고객 로그가 아니라 다른 모델이 구분 설명을 보고 쓴 것이다.
- 정답 구분의 대안 라벨은 개발자가 정했다.
- 맞는 안내가 없는 CS 질문("확인 후 안내"가 정답인 경우)은 평가하지 않는다.
